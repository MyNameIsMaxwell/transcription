# CLAUDE.md — контекст проекта для агента

Читай этот файл в начале каждой сессии. После заметной доработки — допиши запись в «Журнал доработок».

## Что это
Веб-приложение для транскрибации аудио/видео (встречи, интервью) и генерации по транскрипту
структурированного документа через DeepSeek. Результат — два `.docx`: «Резюме» и «Транскрипт» с таймкодами.

Основной сценарий пользователя — **процессный офис**: по записи рассказа отдела или сотрудника
о своей работе получить последовательное текстовое описание процесса «как есть», по которому
потом строится BPMN-диаграмма (шаблон `process`). Встречные сценарии — протокол, задачи, записка руководителю.

## Стек и запуск
- Бэкенд: FastAPI, весь код в одном файле `main.py`.
- Фронт: `index.html` (ванильный JS, inline-скрипт) + `static/style.css`. Дизайн — по `DESIGN.md` (стиль Mintlify).
- Запуск: `python main.py` → http://localhost:8000. Только один uvicorn-воркер (статусы задач в памяти процесса).
- Нужен ffmpeg (в PATH или `FFMPEG_PATH`). Секреты — в `.env`, пример — `.env.example`.
- Venv лежит в `.venv/`. Тестов нет.

## Карта main.py
- `PROMPT_PRESETS` / `resolve_summary_prompt` — шаблоны промптов (`default`, `tasks`, `brief`, `process`).
  Свой промпт из textarea перекрывает шаблон.
- `resolve_summary_model` — модель по шаблону: `process` → `LLM_PROCESS_MODEL` / `DEEPSEEK_PROCESS_MODEL`
  (`deepseek-v4-pro`), остальные → `LLM_MODEL` / `DEEPSEEK_MODEL` (`deepseek-v4-flash` на агрегаторе).
  Если задан `LLM_API_KEY`, запросы идут на `LLM_BASE_URL` (VedAI `https://vedai.by/api/v1`).
- `PROMPT_SHARED_RULES` — общие правила для «встречных» шаблонов (про задачи и таблицу задач).
- `TranscriptionEngine` — движки: `whisper` (faster-whisper, CPU), `speechkit`, `groq`, `stt_api` (OpenAI-совместимый).
- `process_audio` — фоновый пайплайн (ThreadPoolExecutor, 2 воркера):
  `split_audio` (куски по 10 мин) → `transcribe_audio` → `generate_summary` → `create_result_documents`.
- `generate_summary` — две стратегии:
  - обычные шаблоны: длинные тексты (> `SUMMARY_CHUNK_CHARS` = 40k) режет на чанки, извлекает из каждого
    независимо, потом собирает один документ из выжимок (без исходника);
  - `process` (`whole_text=True`): весь транскрипт одним запросом до `WHOLE_TEXT_MAX_CHARS` = 500k символов;
    сверх этого — `_refine_summary`: черновик по 1-й части, каждая следующая часть дополняет черновик
    (+ хвост предыдущей части `REFINE_OVERLAP_CHARS` = 2500 для связки).
- `_add_summary_blocks` — Markdown → docx. Поддерживает только: `#`/`##`/`###`, `- `/`* `, таблицы `|`,
  остальное — обычный абзац (нумерация «1.» остаётся текстом). Жирный `**` не рендерится.
- Статусы задач: память + `task_statuses.json` (`update_task_status`).
- Эндпоинты: `/` (страница, ставит `user_id` в сессию), `/config`, `/upload/`, `/status/{file_id}`,
  `/history`, `/download/{user_id}/{filename}`.
- Результаты: `results/<user_id>/`, загрузки: `uploads/` (рантайм-данные, не коммитить).

## Как добавить шаблон промпта
1. Ключ и текст в `PROMPT_PRESETS` (`main.py`).
2. Кнопка `<button type="button" class="prompt-chip" data-preset="<ключ>">` в `#promptPresets` (`index.html`).
   JS-обработчик и бэкенд подхватывают ключ автоматически.
3. Формат вывода держать в рамках того, что умеет `_add_summary_blocks`.

## Конвенции
- UI, промпты и сообщения — на русском.
- Не ломать поведение существующих шаблонов при правках общего кода.
- Коммиты — только по просьбе пользователя.

## Известные нюансы
- `requirements.txt` в кодировке UTF-16 — может мешать `pip install -r` на Linux.
- `/download` не сверяет `user_id` с сессией; `SESSION_SECRET` имеет небезопасный дефолт.
- `upload_audio` читает файл целиком в память.
