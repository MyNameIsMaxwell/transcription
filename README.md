# Транскрибация аудио

Веб-приложение для транскрибации аудиозаписей встреч с автоматической генерацией структурированного резюме через DeepSeek API.

## Проекты в репозитории

| Папка | Что это | Стек | Как запустить |
|-------|---------|------|---------------|
| `/` (корень) | Транскрибация аудио/видео → резюме и транскрипт в Word | Python 3.10+, FastAPI, ffmpeg | этот README, ниже |
| [`idea-chat/`](idea-chat/) | «Банк идей СТиМ» — чат, который собирает идеи сотрудников в карточку | Node.js 22.5+, Next.js, Yandex Alice AI | [`idea-chat/README.md`](idea-chat/README.md) |

Проекты независимы: у каждого свои зависимости (`requirements.txt` / `idea-chat/package.json`)
и свой файл настроек (`.env` в корне / `idea-chat/.env.local`), примеры — в `.env.example` рядом.

## Возможности

- **Движки транскрибации:**
  - Whisper (локально, CPU, видеокарта не нужна) — через faster-whisper
  - Yandex SpeechKit (облако)
  - Groq Whisper (облако, ~$0.04 за час аудио)
  - любой OpenAI-совместимый STT API
- **Структурированное резюме** — тема, решения, задачи, ключевые тезисы
- **Описание процесса** — последовательное описание работы отдела или сотрудника «как есть» (основа для BPMN-схемы)
- **Экспорт в Word** (.docx): резюме + полный транскрипт с таймкодами
- **Отслеживание прогресса** в реальном времени
- **История обработок** для каждого пользователя
- **Drag-and-drop** загрузка файлов
- **Аудио и видео разных форматов** — M4A, MP3, WAV, OGG, FLAC, AAC, MP4, MOV,
  WebM и другие контейнеры/кодеки, которые умеет читать установленный FFmpeg.
  Формат определяется по содержимому. Перед распознаванием аудиодорожка
  преобразуется в PCM WAV: моно, 16 бит, 16 кГц.

## Системные требования

### Минимальные (для модели Whisper `tiny`)

| Параметр | Значение |
|----------|----------|
| CPU | 2 ядра |
| RAM | 2 GB |
| Диск | 5 GB (ОС + зависимости + модель) |
| ОС | Ubuntu 20.04+ / Debian 11+ |
| Python | 3.10+ |
| Сеть | Доступ к api.deepseek.com |

Подходит для обработки коротких записей (до 15 минут). Транскрибация будет медленной — примерно 2-4x от длительности аудио.

### Рекомендуемые (для модели Whisper `base` / `small`)

| Параметр | Значение |
|----------|----------|
| CPU | 4 ядра |
| RAM | 4 GB (8 GB для модели `small`) |
| Диск | 10 GB |
| ОС | Ubuntu 22.04 / Debian 12 |
| Python | 3.10+ |
| Сеть | Доступ к api.deepseek.com |

Комфортная обработка записей до 60 минут. Скорость транскрибации — примерно 0.5-1.5x от длительности аудио.

### Примечания по ресурсам

- **Модели Whisper по RAM**: `tiny` ~1 GB, `base` ~1.5 GB, `small` ~2.5 GB, `medium` ~5 GB, `large` ~10 GB
- **GPU не требуется** — приложение работает на CPU (compute_type=int8)
- **Параллельная обработка**: каждая одновременная задача потребляет дополнительно ~1 GB RAM (по умолчанию 2 воркера)
- При использовании **только SpeechKit** (без Whisper) достаточно 1 GB RAM и 1 ядра CPU

## Установка

1. Клонируйте репозиторий:
```bash
git clone <url> && cd transcribation
```

2. Создайте виртуальное окружение:
```bash
python -m venv .venv
source .venv/bin/activate
```

3. Установите зависимости (точные версии — в `requirements.txt`):
```bash
pip install -r requirements.txt
```
Проверено на Python 3.10. На Python 3.13+ дополнительно ставится `audioop-lts` (нужен `pydub`) —
это уже прописано в `requirements.txt`.

4. Установите FFmpeg:
```bash
# Ubuntu/Debian
sudo apt-get install ffmpeg

# CentOS/RHEL
sudo yum install ffmpeg

# macOS
brew install ffmpeg
```

5. Создайте файл `.env` на основе `.env.example`:
```bash
cp .env.example .env
```

Заполните `LLM_API_KEY` (агрегатор VedAI) или, если агрегатора нет, `DEEPSEEK_KEY`.

## Конфигурация (.env)

### Обязательные

- `LLM_API_KEY` — ключ агрегатора (VedAI). Если задан, резюме идёт через него
- `LLM_BASE_URL` — OpenAI-совместимый адрес, по умолчанию `https://vedai.by/api/v1`
- `LLM_MODEL` — модель для обычных шаблонов (для VedAI: `deepseek-v4-flash`)
- `LLM_PROCESS_MODEL` — модель для «Описание процесса» (для VedAI: `deepseek-v4-pro`)
- `DEEPSEEK_KEY` — запасной прямой ключ DeepSeek, если `LLM_API_KEY` пустой
- `DEEPSEEK_MODEL` — модель резюме при прямом DeepSeek (по умолчанию `deepseek-flash`)
- `DEEPSEEK_PROCESS_MODEL` — модель процесса при прямом DeepSeek (по умолчанию `deepseek-v4-pro`)
- `DEEPSEEK_PROCESS_THINKING` — режим рассуждения для шаблона процесса: `true`/`false`

### Whisper (локальная транскрибация)

- `WHISPER_MODEL_SIZE` — размер модели: `tiny`, `base`, `small`, `medium`, `large` (по умолчанию: `base`)
- `WHISPER_COMPUTE_TYPE` — тип вычислений: `int8`, `float16`, `float32` (по умолчанию: `int8`)
- `WHISPER_NUM_THREADS` — количество CPU-потоков (по умолчанию: `4`)

### Yandex SpeechKit (облачная транскрибация)

- `YANDEX_API_KEY` — API-ключ Yandex Cloud
- `YANDEX_FOLDER_ID` — ID папки в Yandex Cloud
- `YANDEX_LANG` — язык (по умолчанию: `ru-RU`)

### Groq Whisper (дешёвая облачная транскрибация, без локальной модели)

- `GROQ_API_KEY` — ключ с https://console.groq.com/keys
- `GROQ_STT_MODEL` — по умолчанию `whisper-large-v3-turbo`

Из России `api.groq.com` отвечает 403 без VPN. SpeechKit и локальный Whisper работают напрямую.

### Свой STT API (OpenAI-совместимый)

- `STT_API_BASE_URL` — например `https://api.openai.com/v1`
- `STT_API_KEY` — ключ сервиса
- `STT_API_MODEL` — имя модели, например `whisper-1`

### Google Диск (кнопка «Открыть Google Диск»)

- `GOOGLE_CLIENT_ID` — OAuth 2.0 Client ID типа Web application
- `GOOGLE_API_KEY` — API key с включёнными Google Picker API и Google Drive API
- `GOOGLE_APP_ID` — необязательно, числовой ID проекта Google Cloud

В OAuth-клиенте добавьте Authorized JavaScript origins: `http://localhost:8000` (и ваш домен). Кнопка на странице появляется только когда заданы `GOOGLE_CLIENT_ID` и `GOOGLE_API_KEY`.

### Опциональные

- `FFMPEG_PATH` — путь к ffmpeg, если не в PATH
- `UVICORN_RELOAD` — `true` для dev-режима с автоперезагрузкой

## Запуск

### Локально (разработка)

```bash
python main.py
```

### Продакшн (сервер)

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
```

Не используйте несколько uvicorn-воркеров (`--workers > 1`), так как статусы задач хранятся в памяти процесса.

Для работы через reverse-proxy (nginx):

```nginx
server {
    listen 80;
    server_name your-domain.com;

    client_max_body_size 500M;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 600s;
    }
}
```

Приложение будет доступно по адресу: http://localhost:8000

## Устранение неполадок

**FFmpeg не найден** — убедитесь, что `ffmpeg -version` работает в терминале, или укажите путь через `FFMPEG_PATH`.

На Windows указывайте путь к готовому исполняемому файлу, например
`FFMPEG_PATH=C:\ffmpeg\bin\ffmpeg.exe`. Папка с исходным кодом FFmpeg сама по себе
не содержит работающей программы. Пустой `FFMPEG_PATH` означает поиск в PATH.
Для чтения записей приложение вызывает FFmpeg напрямую; отдельный ffprobe не нужен.
После изменения `.env` перезапустите приложение.

**Ошибка загрузки модели Whisper** — при первом запуске модель скачивается из интернета. Нужен доступ к huggingface.co и ~500 MB-3 GB свободного места.

**Медленная обработка** — используйте меньшую модель (`tiny`) или увеличьте `WHISPER_NUM_THREADS`. Для быстрой обработки используйте SpeechKit.

**Ошибка SpeechKit** — проверьте `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в `.env`.

**SpeechKit: Failed to parse audio for specified audio format** — приложение
отправляет звук как LPCM без WAV-заголовка, моно, 16 бит, 16 кГц, частями до
25 секунд (800 КБ). Это устраняет зависимость от исходного контейнера, количества
каналов и экспортера Ogg Opus. Обновите код и повторно загрузите исходную запись.

**Файл не содержит аудиодорожки / не удалось прочитать запись** — проверьте,
что запись воспроизводится и содержит звук. Поддержка редких кодеков зависит
от сборки FFmpeg; произвольные документы и повреждённые файлы не распознаются.

**SpeechKit: 504 stream timeout** — сервис не успел завершить запрос.
Приложение повторяет временные ошибки HTTP 408/429/500/502/503/504 и сбои
соединения до 3 попыток с паузами 2 и 4 секунды. При повторяющемся таймауте
фрагмент делится пополам; минимальная граница для дальнейшего деления — 5 секунд.
Если сервис продолжает отвечать ошибкой, задача завершается с её текстом и
идентификатором запроса. Ошибки формата и авторизации повторно не отправляются.

## Проверка обработки аудио

После установки зависимостей проекта и FFmpeg:

```bash
python -m unittest discover -s tests -v
```

Проверки генерируют записи в разных форматах, проверяют преобразование, нарезку,
ошибки входных файлов и бинарный запрос SpeechKit. Обращения к облачным API
подменены: ключи и платные запросы не нужны.
